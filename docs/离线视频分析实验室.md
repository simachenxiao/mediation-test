# 离线视频分析实验室 —— 实现说明

本应用位于 `D:/产品/微表情识别/test`，是一个**独立**的离线视频分析页面。
它只读取 `../code` 里的模型、前端运行时和 Python 侧车，**不修改 `../code`**。

页面入口：`http://<host>:3200/`（默认端口 3200，可用 `PORT` 修改）。

---

## 1. 功能拆分

| 模块 | 文件 | 职责 |
|------|------|------|
| HTTP 服务 | `server.mjs` | 静态资源、只读依赖映射、Python 侧车管理、`/physio/estimate` 代理 |
| 抽帧 / 视频解码 | `public/lib/video-frames.js` | 读取元数据、按时间 seek 抽帧、均匀重采样、抽稀 |
| 人脸检测 | `public/lib/face-detect.js` | MediaPipe BlazeFace，供两条链路共用 |
| 面部 ROI 采样 | `public/lib/roi.js` | 额头/左颊/右颊 YCbCr 肤色像素 RGB 均值 |
| **微表情分析** | `public/lib/emotion.js` | 人脸检测 → 裁剪 224×224 → ONNX 8 类情绪 → 时间线/微表情事件 |
| **生命体征检测** | `public/lib/vitals.js` | 人脸框跟随 → ROI 采样 → 均匀重采样 → 分窗口调用 Python 侧车 → 指标汇总 |
| 图表 | `public/lib/charts.js` | 折线 / 条形 / 时间色带（纯 canvas） |
| 页面与交互 | `public/lab.html` + `public/lab.js` | 离线上传、参数、步骤状态、进度、结果表、导出 |
| 实时 A 引擎 | `public/lib/physio-live.js` | 播放中逐帧采样 ROI，30s 窗口 → `/physio/estimate` |
| 实时 A+ 引擎 | `aplus_service.py` | 复用 A 的 payload，POS + Welch + SQI + 稳定器 |
| 实时 B 引擎 | `deep_service.py` | Open-rppg FacePhys.rlap，逐帧接收 JPEG → BVP/HR/SQI |
| 实时对比页 | `public/live.html` + `public/live.js` | 视频 1× 播放，A / A+ / B 并排实时出结果 |
| 确定性重放页 | `public/replay.html` + `public/replay.js` | 固定帧/时间戳/窗口，复跑 A/A+/B，验证可重复性 |

A、A+、B 共享基础工具（抽帧、人脸检测、ROI 采样）；A 和 A+ 共用同一份 ROI 采样，B 使用整帧图像。三者算法与结果相互独立。

## 2. 启动与依赖

```bash
cd D:/产品/微表情识别/test
npm start
# 等价于 node server.mjs
```

`server.mjs` 只使用 Node 内置模块，**不需要在 test 目录 npm install**。
但需要 `../code` 中已存在：

```
../code/node_modules/@mediapipe/tasks-vision
../code/node_modules/onnxruntime-web/dist
../code/models
../code/physio_service
```

生命体征还需要：

```bash
pip install -r ../code/physio_service/requirements.txt
```

Python 解释器默认：Windows 用 `python`，Linux/macOS 用 `python3`；可用 `PHYSIO_PYTHON` 覆盖。

### 2.1 实时 A / A+ / B 对比

浏览器打开 `http://localhost:3200/live`。B 引擎还需要：

- `../EmotiEffLib-main/rppg-demo/rppg-demo/vendor/open_rppg`
- Python 依赖：`jax`、`keras`、`onnxruntime`、`opencv-python`、`heartpy`

```bash
pip install "jax" "keras>=3" onnxruntime opencv-python heartpy
```

B 模型首次加载约 20–40 秒；加载完成后才能开始。视频按 1× 播放，A/A+/B 都使用 30 秒滑动窗口，
播放期间禁用进度条拖动，避免时间戳回退导致 B 模型重置。

A+ 是纯 NumPy/SciPy 侧车，不需要额外模型；它复用 A 的 ROI payload，
增加平滑先验去趋势、0.8–3.5Hz + 0.6–3.5Hz 双频带、POS 单方法、双 ROI 共识簇、Welch、SQI 和稳定器。
详细设计见 [方法A的问题与A+改进.md](方法A的问题与A+改进.md)。

### 2.2 确定性重放

浏览器打开 `http://localhost:3200/replay`。它按固定 15fps seek 抽帧，固定每 5 帧检测一次人脸，
在固定 30 秒窗口和每秒检查点上复用同一份 payload；A/A+ 自动复跑两次逐点比较，
A+/B 稳定器使用视频时间 `replayTime`。B 可点“再跑一次并对比”验证第二次。

实时页用来观察边播边算；重放页用来判断结果变化来自输入采样还是算法/状态。

## 3. 分步结果

### 微表情

1. **视频解码与抽帧规划**：时长、分辨率、目标帧率、计划帧数、首帧预览。
2. **人脸检测**：逐采样帧绘制人脸框；拖动滑块回看任意帧，显示检出率与平均人脸数。
3. **人脸裁剪与归一化**：逐帧缩略图；点击查看大图、人脸框尺寸、224×224 输入、RGB 均值。
4. **情绪推理**：当前帧 8 类情绪概率条形图、推理引擎/耗时、逐帧结果表。
5. **微表情时间线**：主导情绪时间带、8 类概率曲线、负向占比、短时非平静表情事件表。

微表情事件定义：连续同类情绪、持续 ≤ 1.2s、平均置信度 ≥ 0.4、且不是「平静」。
可在 `analyzeEmotion()` 的 `microMaxSec` / `microMinConf` 参数中调整。

### 生命体征

1. **人脸跟踪与 ROI 定位**：人脸框 + 三路 ROI 叠加；拖动滑块回看任意采样帧。
2. **ROI 像素采样曲线**：R/G/B 或归一化绿通道，观察脉搏引起的微弱周期波动。
3. **分窗口信号估计**：按窗口（默认 20s / 步长 5s）调用 `/physio/estimate`，逐行追加 HR/RR/SpO₂/质量。
4. **生理指标汇总**：心率（中位/最新）、呼吸率、血氧、血压、HRV、信号质量，以及心率随窗口的变化曲线。

> SpO₂ 与血压为普通 RGB 摄像头下的**估计值**，非医疗级，系数需逐设备、逐人标定。

## 4. 模块 API（可单独复用）

### 微表情

```js
import { analyzeEmotion } from '/lib/emotion.js';

const result = await analyzeEmotion(videoElement, {
  fps: 5,              // 每秒分析帧数
  maxSeconds: 60,      // 0 = 全部
  forceEp: '',         // '' | 'webgpu' | 'wasm'
  microMaxSec: 1.2,
  microMinConf: 0.4,
  signal,              // AbortSignal
}, {
  onProgress({ done, total }) {},
  onFrame(frame, { frameCanvas }) {},   // frame.box / label / confidence / probs
  onLog(msg) {},
});

result.frames      // 每采样帧：{t, box, label, probs, ...}
result.samples     // 检出人脸的帧
result.timeline    // 主导情绪连续段
result.events      // 微表情事件
result.summary     // 检出率、主导情绪、负向占比、平均推理耗时…
```

### 生命体征

```js
import { analyzeVitals } from '/lib/vitals.js';

const result = await analyzeVitals(videoElement, {
  fps: 15,
  maxSeconds: 0,
  detectEverySec: 0.5,   // 人脸检测频率（框跟随）
  windowSec: 20,
  stepSec: 5,
  signal,
}, {
  onProgress({ phase, done, total }) {},
  onSample(sample, { frameCanvas }) {},
  onWindow(win, { total }) {},
  onLog(msg) {},
});

result.traces     // 抽稀后的三路 ROI 颜色曲线（画图用）
result.windows    // 每个窗口的 /physio/estimate 返回
result.summary    // HR/RR/SpO₂/BP/HRV/质量 汇总
```

## 5. 服务端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` 或 `/lab` | 离线分析页面 |
| GET | `/health` | 服务健康检查 |
| GET | `/physio/health` | 侧车状态（running / port / logs / lastError） |
| POST | `/physio/restart` | 重启侧车 |
| POST | `/physio/estimate` | 转发给侧车，返回生理指标 JSON |

侧车由 `server.mjs` 在服务启动时自动拉起；页面上的「检查」按钮在未运行时会触发重启。

## 6. 实现要点与限制

- **逐帧 seek**：不依赖播放帧率，时间戳与视频真实时间一致；长视频会比实时播放慢，但结果可复现。
  可用「分析时长上限」限制处理长度。
- **人脸框跟随**：生命体征每 0.5s 检测一次人脸，框丢失后最多复用 1.5s，减少抖动与开销。
- **独立解码实例**：预览、微表情、生命体征各用一个 `<video>`，互不干扰；分析串行执行。
- **引擎**：情绪推理优先 WebGPU（仅硬件适配器），否则 WASM；可用下拉框强制。
- **视频编码**：依赖浏览器解码能力。个别精简版 Chromium 可能缺少 H.264 或特定编码，
  可先在页面上用预览确认能播放。
- **隐私**：视频只在浏览器本地解码，不上传；只有 ROI 颜色数值会 POST 给本机 Python 侧车。
- **导出**：每个模块都有 JSON / CSV 导出，便于离线复核或算法对比。
